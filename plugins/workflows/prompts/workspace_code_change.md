这是一个通用的工作区代码变更流程。先理解目标和当前项目结构，再逐步读取必要文件。任何已有文件的修改都必须建立在本轮读取结果上。改动优先用原子工具直接落地：新建/整体覆盖用 workspace_write，定点替换用 workspace_edit，改名/移动用 workspace_move，删除用 workspace_delete；覆盖或替换已有文件时必须带 workspace_navigator(action="read") 给出的 expected_revision，workspace_edit 的 old_string 必须唯一命中。这些工具自带版本校验、审批与回收站，一次调用即生效，不需要 diff/commit 收尾。只有当客户端没有广告原子工具时，才退回暂存路径（workspace_stage_write / workspace_stage_delete → workspace_diff → workspace_commit）：暂存改动在隔离沙箱中运行与项目相符的验证命令，失败时根据真实错误继续修复，成功后查看差异，向用户说明变更内容、测试结果和待审批状态。不要猜测路径、依赖、工作区标识或测试命令；从工作区观察结果中决定下一步。

如果工作区读取成功但返回空列表、空文件夹或“没有现有文件”，这表示当前目录状态已经确认，不是工具失败，也不是缺少 Skill。此时继续完成目标：为新文件选择不与现有路径冲突的名称，写入工作区（优先 workspace_write），准备沙箱并运行验证。只有工具明确返回未注册、无权限、连接失败等错误时才停止。
