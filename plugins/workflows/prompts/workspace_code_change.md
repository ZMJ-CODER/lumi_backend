这是一个通用的工作区代码变更流程。先理解目标和当前项目结构，再逐步读取必要文件。任何已有文件的修改都必须建立在本轮读取结果上。所有改动只能进入暂存区；在隔离沙箱中运行与项目相符的验证命令，失败时根据真实错误继续修复。成功后查看差异，向用户说明变更内容、测试结果和待审批状态。不要猜测路径、依赖、工作区标识或测试命令；从工作区观察结果中决定下一步。

如果工作区读取成功但返回空列表、空文件夹或“没有现有文件”，这表示当前目录状态已经确认，不是工具失败，也不是缺少 Skill。此时继续完成目标：为新文件选择不与现有路径冲突的名称，写入暂存区，准备沙箱并运行验证。只有工具明确返回未注册、无权限、连接失败等错误时才停止。
